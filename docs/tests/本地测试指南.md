# 本机 Docker 快速验证（OpenSandbox + 真实 codex）

用于在开发机验证「控制面 → OpenSandbox → 沙箱容器 → 桥接 → 真实 codex」链路，不依赖内网。
本机实测通过：沙箱创建、codex `initialize`/`thread/start`、`turn/start` 打到网关（未配上游时 503）、pause/resume、销毁。

## 前置

- Docker（Docker Desktop 可用）、`uv`、Node/pnpm（仓库已用镜像站拉包时无需额外配置）。
- 若 Docker Hub 不可直连，用镜像站前缀替换基础镜像（示例：`docker.1ms.run/library/...`）。
- Debian 源不可达时给构建传 `APT_MIRROR`（示例：`mirrors.tuna.tsinghua.edu.cn`）。

## 1. 构建沙箱镜像

```bash
docker build -f sandbox/images/Dockerfile \
  --build-arg NODE_IMAGE=docker.1ms.run/library/node:22-slim \
  --build-arg PYTHON_IMAGE=docker.1ms.run/library/python:3.12-slim-bookworm \
  --build-arg APT_MIRROR=mirrors.tuna.tsinghua.edu.cn \
  -t cloud-agents/sandbox:0.1.0 .
```

## 2. 启动 OpenSandbox 服务端

```bash
uvx opensandbox-server init-config /tmp/sandbox.toml --example docker --force
```

改四处后启动（`NO_PROXY="*" uvx opensandbox-server --config /tmp/sandbox.toml`，NO_PROXY 原因见「已知坑」）：

- `[server] api_key = "test-key"`
- `[runtime] execd_image = "docker.1ms.run/opensandbox/execd:v1.1.0"`（按可拉取的镜像站/版本）
- `[storage] allowed_host_paths = ["<仓库绝对路径>/.local/volumes"]` —— **留空会拒绝所有 host 挂载**，
  必须覆盖控制面的 `WORKSPACE_HOST_ROOT`。
- 追加 `[egress]` 段（沙箱默认全拒的执行层，**mode 必须 `dns+nft`**）：

  ```toml
  [egress]
  image = "docker.1ms.run/opensandbox/egress:v1.1.7"
  mode = "dns+nft"
  ```

  `[docker] network_mode = "bridge"` 示例默认已是。`dns` 模式只拦 DNS 解析、直连 IP 可绕过，
  不满足默认全拒（2026-11-18 实测，见 §6 与 [验证记录](2026-11-18-P1-egress与cgroup验证.md)）。

## 3. 启动控制面（本机 SQLite 台账）

```bash
mkdir -p .local/volumes
DATABASE_URL="sqlite+aiosqlite:///D:/path/to/cloud-agents/.local/ledger.db" \
  uv run --directory control-plane alembic upgrade head

PUBLIC_BASE_URL=http://host.docker.internal:8000 \
P1_AUTH_TOKEN=local-owner P1_OWNER=local-user \
OPENSANDBOX_BASE_URL=http://127.0.0.1:8080 OPENSANDBOX_API_KEY=test-key \
SANDBOX_IMAGE=cloud-agents/sandbox:0.1.0 SANDBOX_START_TIMEOUT_SECONDS=120 \
WORKSPACE_HOST_ROOT="$PWD/.local/volumes" \
DATABASE_URL="sqlite+aiosqlite:///D:/path/to/cloud-agents/.local/ledger.db" \
  uv run --directory control-plane uvicorn app.main:app --host 0.0.0.0 --port 8000
```

要点：

- SQLite 连接串用绝对路径：Windows 写盘符（`sqlite+aiosqlite:///D:/...`），Linux/macOS 写 `sqlite+aiosqlite:////abs/path`。
- `PUBLIC_BASE_URL` 是**沙箱容器视角**的控制面地址，本机必须用 `host.docker.internal`（Linux 主机用宿主机 IP）。
- 控制面必须监听 `0.0.0.0`，否则容器连不上。
- `WORKSPACE_HOST_ROOT` 必须在 OpenSandbox 的 `allowed_host_paths` 下。

## 4. 创建会话并验收

```bash
curl -s -X POST http://127.0.0.1:8000/api/sessions \
  -H "Authorization: Bearer local-owner" -H "Content-Type: application/json" -d '{}'
```

返回 `ws_url` 后浏览器打开 `http://127.0.0.1:5173/?session=<id>&token=<token>&ws=ws://127.0.0.1:8000`
（先 `pnpm -C web dev`）。

命令行验收：用任意 WebSocket 客户端连接 `ws://127.0.0.1:8000/ws/session/<id>?token=<token>`，
发 `{"id":1,"method":"initialize","params":{"clientInfo":{"name":"smoke","version":"0"}}}`，
应收到 `userAgent` 含 codex 版本的结果；`thread/start` 返回 thread。

## 5. 模型与清理

- 未配 `LLM_UPSTREAM_BASE_URL` 时，`turn/start` 会收到 503（网关明确拒绝，codex 重试 5 次后失败）——这是预期，不是链路故障。
- **上游必须是 Responses API**：codex 0.167 已移除 `wire_api = "chat"`，只请求 `{base_url}/responses`。
  实测智谱（`/api/paas/v4`）只有 chat completions，`/responses` 返回 404，不能直接用。
- 已实测可用组合（DeepSeek flash，两轮对话 + `thread/resume` 均通过）：

  ```bash
  LLM_UPSTREAM_BASE_URL=https://api.deepseek.com
  LLM_API_KEY=<deepseek-key>
  CODEX_MODEL=deepseek-flash          # 只配 flash，避免误用 pro 抬高费用
  CODEX_REASONING_EFFORT=minimal      # 关闭思考
  CODEX_CONTEXT_WINDOW=100000         # 上下文限制 100k
  ```

  这三个 `CODEX_*` 会写进容器内 `/home/agent/.codex/config.toml`；
  验证：`docker exec <容器> cat /home/agent/.codex/config.toml`。
- 销毁：`curl -X DELETE http://127.0.0.1:8000/api/sessions/<id> -H "Authorization: Bearer local-owner"`，
  确认 `docker ps` 无 `sandbox-*` 容器、台账 `sessions.status=ended`。

## 6. egress 强制验证

前置：§2 已配 `[egress] mode="dns+nft"`；控制面按 §3 启动（默认 `SANDBOX_NETWORK_DEFAULT_ACTION=deny`，`SANDBOX_EGRESS_ALLOW` 为空 = 仅放行控制面/网关）。创建会话后：

```bash
SBX=<返回的 sandbox_id>
# 策略下发证据：sidecar 收到的规则
docker inspect "sandbox-egress-$SBX" --format '{{json .Config.Env}}' | grep EGRESS_RULES
# 限额证据（预期 2 CPU / 2GiB / pids 4096；ReadonlyRootfs=false 为 P4 遗留）
docker inspect "sandbox-$SBX" --format 'NanoCpus={{.HostConfig.NanoCpus}} Memory={{.HostConfig.Memory}} PidsLimit={{.HostConfig.PidsLimit}} ReadonlyRootfs={{.HostConfig.ReadonlyRootfs}}'
```

沙箱内三层出口测试（预期：网关 200、公网 DNS 拒、直连 IP 拒）：

```bash
docker exec "sandbox-$SBX" timeout 40 python -c "
import socket, urllib.request
print('gateway:', urllib.request.urlopen('http://host.docker.internal:8000/healthz', timeout=8).status)
for host in ('api.deepseek.com', 'example.com'):
    try:
        socket.getaddrinfo(host, 443); print('dns', host, ': RESOLVED（不应出现）')
    except OSError: print('dns', host, ': BLOCKED')
for ip in ('1.1.1.1', '8.8.8.8'):
    try:
        s = socket.create_connection((ip, 443), timeout=8); s.close(); print('tcp', ip, ': CONNECTED（不应出现）')
    except OSError: print('tcp', ip, ': BLOCKED')
"
```

硬编码 DNS 服务器同样被拦：`dns+nft` 把 53 端口透明重定向到 sidecar 过滤，向 `8.8.8.8:53` 查
`example.com` 应得 NXDOMAIN（rcode=3），查 `host.docker.internal` 应正常解析；DoT（853）被显式丢弃。

白名单扩展：控制面加 `SANDBOX_EGRESS_ALLOW="api.deepseek.com,1.1.1.1:443"` 重启后重建会话，
沙箱内 `api.deepseek.com` 可解析连通、`1.1.1.1:443` 可连，其余仍拒。
**`ports` 不被 sidecar v1.1.7 执行**：`1.1.1.1:80` 也会通——白名单实际 IP 级，升级 sidecar 须复测。

真实模型 turn 按 §4/§5 走（WS 冒烟或真模式 Playwright）；egress 强制下已实测通过。
完整证据与 nft 规则集见 [验证记录](2026-11-18-P1-egress与cgroup验证.md)。

## 7. compose + Postgres（L7 部署路径）

compose 用 Postgres 17 替换本机 SQLite，控制面启动时自动跑 Alembic。实跑记录见
[compose 与 Postgres 验证](2026-11-18-P1-compose与Postgres验证.md)。

1. 从 `sandbox/opensandbox/config.example.toml` 复制一份本机配置（如 `.local/compose-sandbox.toml`，不入库）：
   `[server] host = "0.0.0.0"`、`[docker].host_ip = "host.docker.internal"`、
   `allowed_host_paths` 指向本机工作区绝对路径（Windows 用 `D:/...`），execd/egress 镜像按本机可拉取的 pin 填。
2. `.env` 的 `SANDBOX_CONFIG_PATH` 是 compose 插值用的宿主路径；Git Bash 的 `/tmp/...` Docker Desktop 不认，
   在 PowerShell 里覆盖为 Windows 绝对路径：

   ```powershell
   $env:SANDBOX_CONFIG_PATH='D:\ssd-projects\cloud-agents\.local\compose-sandbox.toml'
   docker compose -f deploy/compose.yaml --env-file .env up -d --build
   ```

   compose 已固定控制面访问 OpenSandbox 的地址为 `http://opensandbox:8080`，无需改 `.env`；
   opensandbox-server 版本 pin 在 compose 内（1.2.1）。

3. 验收：`curl http://127.0.0.1:8000/healthz` → ok；`POST /api/sessions` 正常返回；
   浏览器用 `ws=ws://127.0.0.1:8000` 覆盖 `ws_url`（`PUBLIC_BASE_URL` 给沙箱用的是宿主地址）。

4. 只验迁移（在控制面容器内跑，与部署路径一致）：

   ```powershell
   docker compose -f deploy/compose.yaml --env-file .env up -d --build
   docker compose -f deploy/compose.yaml --env-file .env exec control-plane alembic current
   docker compose -f deploy/compose.yaml --env-file .env exec control-plane alembic check
   ```

5. 清理：`docker compose -f deploy/compose.yaml --env-file .env down`（保留 `pgdata`/`osbdata` 卷；
   `down -v` 会删数据）。

## 已知坑

- **上游压缩 SSE**：网关曾用 `aiter_raw()` 透传，gzip 字节被原样送出导致 codex 报
  `UTF8 error: invalid utf-8 sequence`；已改为 `aiter_bytes()` 并有回归测试。
- **codex 0.167 只支持 Responses API**：chat-only 上游（智谱、Ollama 等）需额外协议转换，
  P1 不做；换模型前先确认 `POST {base_url}/responses` 可用。
- Debian `trixie-updates` 源在部分网络会 500；本机改用了 `bookworm` 基础镜像 + `APT_MIRROR`。
- OpenSandbox 的 `allowed_host_paths` 为空表示**拒绝**，与部分文档描述相反，以实际报错为准。
- 本机首次建表必须跑 `alembic upgrade head`（compose 里已自动执行）。
- 受限沙箱里 `pnpm run check` 不跑前端覆盖率（覆盖率临时目录的批量删除会被拦截）；
  需要门槛时单独跑 `pnpm -C web run test:cov`（CI 应跑这个）。
- `.env` 里不要写 `WORKSPACE_MOUNT_PATH=/workspace`：Git Bash 会把它转换成安装路径；
  用 `Settings` 默认值即可。加载方式：`set -a; . ./.env; set +a`。
- **开发机代理 bypass 含 `[::1]`**：httpx 0.28.1 解析为非法端口，`uvx opensandbox-server` 与控制面
  启动即崩（`Invalid port: ':1]'`）。两者都以 `NO_PROXY="*" no_proxy="*"` 前缀启动规避
  （pytest 已由 conftest 固定，门禁不受影响）。这是开发机现象；部署机须无系统代理或显式 NO_PROXY（方案 §6）。

## 真实验收结果（2026-11-18，DeepSeek flash）

完整报告见 `2026-11-18-P1-验收报告.md`。

| 项 | 结果 |
|---|---|
| 容器内 codex 握手 / 建 thread | 通过（codex-cli 0.167.0，Debian 12） |
| 真实对话（turn/start + 流式增量） | 通过，`pong`，约 1s |
| 工具调用 + 审批 | 通过：`cat /etc/hostname` 审批后执行，输出回传 |
| 文件写入 + host 卷 | 通过：容器内 `/workspace/hello.txt` 在 `.local/volumes/<session>/` 可见 |
| pause → resume → `thread/resume` 续聊 | 通过（仍答 `ok`） |
| 浏览器金路径 | 通过：发送 → 流式回复；刷新重连后仍显示「已连接」 |
| 指标 | `/metrics` 中 `cloud_agents_active_sessions 1.0` |
| 控制面重启 | 启动对账把残留 `running` 标记 `ended`（reason=control_plane_restart） |

真模式 Playwright（需先起 OpenSandbox + 控制面 + Vite，并创建会话）：

```bash
cd web
E2E_REAL_SESSION_URL="http://127.0.0.1:5173/?session=<id>&token=<token>&ws=ws://127.0.0.1:8000" \
  pnpm exec playwright test --config playwright.real.config.ts
```

实测发现并修复的两个真问题：

1. **容器内 bwrap 不可用**：codex 默认 `workspace-write` 会尝试创建 user namespace，
   容器内报 `bwrap: No permissions to create a new namespace`。P1 的隔离边界是容器本身，
   桥接默认写 `sandbox_mode = "danger-full-access"`、`approval_policy = "on-request"`，
   可用 `CODEX_SANDBOX_MODE` / `CODEX_APPROVAL_POLICY` 覆盖。
2. **initialize 只能一次**：真 codex 每进程只允许初始化一次，浏览器刷新/重连会收到
   `Already initialized`。桥接现在缓存首次 `initialize` 结果并对后续客户端本地应答。
