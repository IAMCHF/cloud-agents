## 功能与证据

### 1. 云端会话列表

`GET /api/sessions` 只返回当前属主的会话（`session_id/status/created_at/ended_at/archived_at`）。Web OIDC 登录后展示列表：

- `idle` 会话「恢复并打开」→ `POST /api/sessions/{id}/resume`，记住新 token 并跳转；
- `running` 会话只有浏览器 `localStorage` 记住原 token 时才能打开，否则提示使用原会话链接；
- `ended` 会话不可打开，归档会话显示「已归档」。

### 2. 线程列表与恢复

`connect()` 顺序：`initialize` → `thread/list` → 有历史线程则 `thread/resume` 最近一条，否则 `thread/start`。

- `thread/resume` 返回的 `turns[].items` 归约为对话项（`userMessage` 从 `content[]` 提取文本）；
- 左侧「任务线程」可切换线程，新建线程按钮调用 `thread/start`；
- 断线重连时保留未决审批（`newThread(false)` / `resumeThread(id, false)`），避免先收到审批补发又被新线程清空。

mock 单测覆盖：历史线程恢复、`turn/diff/updated`、`turn/plan/updated`、new thread 清空 diff。

### 3. Diff 与计划

- `turn/diff/updated` 写入 store，右侧 CodeMirror 6 只读视图按行着色（新增/删除/hunk/文件头）；
- `turn/plan/updated` 渲染「本轮计划」，状态 pending/inProgress/completed；
- fake codex 在 turn 中发送 diff 与 plan 通知；Playwright mock 金路径断言 `diff-view` 可见、`+hello` 与「执行命令」可见。

**偏离**：原计划写 `@codemirror/merge`，但它需要原文/修改后两份文档；codex 只给 unified diff 字符串。因此用 CodeMirror 6 核心做只读行级 diff 渲染（未引 `@codemirror/merge`），语义不变。

### 4. 真模型 kind 验证

创建会话 `s-02ef9ff1...`，端口转发到持有桥接的控制面副本，Vite 5175 打开：

- Playwright 真模型用例通过（发送「只回复 pong」→ 看到 `pong` → 刷新后仍「已连接」）；
- 刷新后 `thread/list` 找到线程并 `thread/resume` 回放历史，验证了 Web 的线程恢复路径。

## 缺陷与修复

1. **E2E mock stack 启动失败（no such table: sessions）**：T1 启动对账在 `build_components` 中查库，而 mock stack 从未建表。启动前用 `Database.create_schema()` 建表。
2. **重开页面未决审批丢失**：`newThread()` 无条件清空 approvals，覆盖了桥接刚补发的审批。改为 `newThread(clearApprovals=false)` 默认保留；UI 显式新建/切换线程传 `true`。
3. **Biome lint/format**：import type、hook 依赖、数组 index key、格式化一次清理。

## 未覆盖风险

- `running` 会话重开依赖浏览器 `localStorage` 记住 token；换浏览器/清存储只能使用原链接。
- Ingress 滚动更新/多副本下的 WS 握手重试仍未加到 Web（P3 T7）；真模型验证走端口转发直连桥接副本。
- `thread/list` 只取最近 50 条，无分页 UI。
- CodeMirror diff 是行级只读展示，未做 hunk 折叠/逐块接受。
- 会话列表无标题（只显示 session_id），线程标题取 name/preview。
- 真实 OIDC 浏览器 PKCE 全流程未在 T4 复跑（P2 已验 token 校验）。
