# 2026-11-18 P1.5 K8s 运行时与 PVC 全链路验证

P1.5 目标：把运行时/存储抽象落到代码，支持 K8s 的会话级 PVC，并在 kind 上把
“控制面 + Postgres + OpenSandbox + 桥接 + 真实 turn”完整跑通，与 Docker 路径共用同一套
管理/执行 API。结论：**K8s 后端全链路通过；PVC 按会话创建、销毁沙箱后保留；pause 仍不支持，
P3 走冷恢复。**

| 验证项 | 证据 |
|---|---|
| PVC | `ws-s-4f62...` Bound，1Gi，RWO，StorageClass `standard` |
| 沙箱 Pod | `4967...-0  2/2 Running`（sandbox + egress sidecar） |
| 桥接 | 控制面日志 `WebSocket /ws/bridge/s-4f62... [accepted]` |
| 真实 turn | WS `initialize` 返回 `l7-smoke/0.167.0 (Debian 12.0.0; x86_64)`；`turn completed: completed` |
| 工作区 | Pod 内 `/workspace/hello.txt` 内容 `p15-ok`，属主 `agent:agent`（落在 PVC） |
| 台账 | Postgres `sessions.status=running`；审计 `session.created` |
| 指标 | `cloud_agents_active_sessions 1.0` |
| 销毁 | `DELETE` 返回 204；沙箱 Pod 回收；台账 `ended/stopped`；审计增加 `session.stopped`；指标回 0 |
| PVC 保留 | 沙箱删除后 `ws-s-4f62...` 仍 Bound（`deleteOnSandboxTermination=false`），供 P3 冷恢复/归档 |

## 4. 未覆盖与风险

- **pause/resume**：K8s 默认无 snapshot registry，`PauseFailed`；P3 用“销毁 + 卷持久化 + 冷启动”，本记录验证了卷在沙箱删除后仍在。
- **单副本**：控制面 Deployment 1 副本；P2 HA 需要入口粘性/共享 Postgres。
- **存储实现**：kind 默认 `local-path`，不是 NFS；真实 NAS 的 PV/StorageClass/权限留 D2。
- **PVC 清理**：当前保留用户卷，P3 归档/配额回收前会累积；需在执行机加清理策略。
- **口令拼接**：`DATABASE_URL` 由 `$(POSTGRES_PASSWORD)` 拼接，生产口令含 URL 特殊字符需编码。
- **镜像注入**：Docker Desktop 需 `--provenance=false --sbom=false` 才能 `kind load`；内网走 registry。
- **Docker 回归**：本次未重跑 Docker 全链路；P1 验收与 L7 compose 记录可作基线，P2 前再回归一次。
