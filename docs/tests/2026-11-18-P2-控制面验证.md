`deploy/k8s/README.md` §2–4.1；本文件记录当次环境、证据与未覆盖风险。

## 验证项与证据

### 1. OIDC 真实 token（Keycloak）

- 从 `http://127.0.0.1:8081/realms/cloud-agents/.../token` 取 `cloud-agents-svc`
  client_credentials token，用 `OidcProvider`（discovery → JWKS → 签名/claims）校验：
  输出 `ok Principal(...)`。
- 篡改签名末位后校验抛 `OidcError`（拒绝）。
- OIDC 模式下 REST/WSS 的属主校验、`AUTH_MODE=token` 回退由单测覆盖（`tests/test_auth.py`、
  `tests/test_hub_server.py::test_rebuilds_channel_from_ledger_on_connect`）。

### 2. 迁移与双副本

- 双副本启动后 `kubectl -n cloud-agents get pods` 两个 `1/1 Running`；其中一副本执行了
  `0002_tenants_usage`，另一副本启动无冲突。
- `PodDisruptionBudget minAvailable: 1` 生效；滚动策略 `maxUnavailable: 0`。

### 3. 配额（同属主/租户）

- `POST /api/sessions` 第 1 个返回 200；同属主再次创建返回 **429**，body 含
  “同用户已有活跃会话”（同属主上限 1，先于租户默认 2 触发）。
- 租户级额度（`tenants.monthly_token_budget` / `max_active_sessions`）的 SQL 判定由 T3
  单测覆盖；真实多 OIDC 用户的租户额度留内网 D2 复跑（见未覆盖风险）。

### 4. LLM 计量

- 真实 turn 经网关转发后，`llm_usage` 落库（Postgres 查询）：
  `deepseek-flash | 9299 | 5`、`deepseek-flash | 9316 | 5`（两次续聊），手工 probe
  `32 | 37`。
- `/metrics` 出现 `cloud_agents_llm_tokens_total{direction="input"|"output",tenant="default"}`
  与 `cloud_agents_llm_requests_total`；预算拒绝计数由单测覆盖。
- 网关鉴权已改为台账 `sessions.token_hash` 反查（重启/换副本后仍可校验）。

### 5. 多客户端扇出

- 同一会话两个 WS 客户端同时在线：客户端 A 发起 `turn/start`，客户端 B 完整收到
  `turn/started` → `item/agentMessage/delta` → `turn/completed`（无缺失）。
- 审批补发到新连接、重复响应首个生效/重复丢弃、慢客户端队列断开由
  `tests/test_hub_server.py` 与 `tests/test_bridge_integration.py` 覆盖。

### 6. HA：杀 Pod 后 resume

1. 桥接持有副本 `control-plane-b7d96bc59-ff6jq` 被 `kubectl delete pod`。
2. 桥接重连到存活副本（`c4x8r`），新副本 `c2hnp` 加入；控制面按台账重建通道，
   台账会话保持 `running`（启动对账未误杀）。
3. 客户端经 Ingress 重连 + `thread/resume` → 新 turn 完成，回复 `failover-ok`。
4. 再做一次**双副本滚动重启**（两个 Pod 全换），重连后 `thread/resume` → 回复
   `heal-ok`；期间客户端落在无桥接副本时被 HTTP 403 拒绝，由 Ingress 换副本重试后成功。

### 7. 删除会话与卷

- `DELETE /api/sessions/<id>` 返回 204；沙箱 Pod 回收、台账 `ended/stopped`；
  会话级 PVC `ws-<session_id>` 仍 `Bound`（保留语义与 P1.5 一致）。

## 发现与修复

| 问题 | 现象 | 修复 |
|---|---|---|
| 计量丢账 | codex 收到 `response.completed` 即断开，流末尾的 `finally` 写库被取消，`llm_usage` 无行 | 解析到 usage 立即落库（`e153454`）；修复后真实 turn 均有行 |
| 入口哈希漂移 | 副本增减后桥接留在旧副本，新客户端哈希到新副本，持续 1013 | 握手阶段无桥接返回 403（不 accept），Ingress `proxy-next-upstream http_403` 换副本重试（`00f36f6`）；滚动重启后 resume 实测成功 |

## 未覆盖风险

- 租户月度预算的 **Postgres 真链路 429** 未跑（缺管理面设置租户预算入口，当前仅单测）。
- Keycloak **浏览器 PKCE 登录**未做真机全流程（Web 登录态为单测 + mock）；OIDC 多用户
  的租户共享/额度留 D2。
- Web 客户端对握手 403 的**自动重试**未实测（页面断开后需手动重连；服务端已收敛，
  客户端退避策略 P3 复核）。
- 滚动更新期间新 Pod 加入的短暂 403 窗口依赖客户端重试；PDB 只保证至少 1 副本。
- 入口用 nip.io + socat 属开发机方案；内网按真实负载均衡域名/TLS 接入（D2）。
