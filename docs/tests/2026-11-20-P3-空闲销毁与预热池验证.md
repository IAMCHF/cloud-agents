# 2026-11-20 P3 T2 空闲销毁与预热池验证

结论：**空闲销毁 PASS**（会话自动转 idle、沙箱回收、双卷保留、可恢复）；**预热池不可用，按计划降级**（OpenSandbox `poolRef` 拒绝每会话卷与 `networkPolicy`，与隔离/egress 基线冲突）。

## 环境

| 项 | 值 |
|---|---|
| 集群 | kind `cloud-agents-dev`，控制面双副本 + Postgres + OpenSandbox K8s 运行时 |
| 控制面 | `cloud-agents/control-plane:p3`，提交 `3a6ae96` |
| 空闲参数（验证用） | `IDLE_TIMEOUT_SECONDS=10`、`IDLE_SWEEP_INTERVAL_SECONDS=5`（验证后已移除，恢复默认 900/60） |
| 审批超时 | 默认 300s（本轮未构造无人审批场景） |

## 1. 空闲销毁

创建会话 `s-aca11fc1a66f4d8b925145872de07557`，不连接客户端，等待 sweeper：

- `GET /api/sessions/<id>` → `status=idle`，`sandbox_id=null`。
- 沙箱 Pod `76a46ab0-...` 已回收。
- `ws-s-aca11...` 与 `state-s-aca11...` 两个 PVC 仍 `Bound`。
- 审计：`session.created` → `session.idled`。
- 指标（持有该通道的副本）：
  `cloud_agents_idle_sessions_slept_total{reason="idle"} 1.0`；
  另一副本 `cloud_agents_sandbox_create_seconds_count{mode="create"} 1.0`（创建会话所在副本）。
- 恢复：`POST /api/sessions/<id>/resume` → **200**，返回新 token 与新沙箱；随后 `DELETE` → **204**。

行为边界：

- 有客户端连接时 sweeper 不销毁；显式 `POST /sleep` 可强制断开空闲客户端（仍不打断进行中的 turn/未决审批）。
- 有进行中 turn（`turn/started` 未收到 `turn/completed`）时不销毁，保证关页任务继续跑。
- 未决审批：仅 `*requestApproval` 会按 `APPROVAL_TIMEOUT_SECONDS` 自动 decline；`item/tool/requestUserInput` 等结果形状不同，超时不自动应答，保持挂起（会阻止空闲销毁，需客户端处理或 DELETE）。

## 2. 预热池 spike

1. `POST /v1/pools` 创建 `p3-spike`（1 个预热 Pod）→ **201**，`status.available=1`，Pod `p3-spike-gctqj` Running。
2. 从池分配沙箱并带 `networkPolicy`：
   - **400** `networkPolicy cannot be used together with extensions.poolRef because pooled pods are pre-created.`
3. 去掉 `networkPolicy`、保留每会话卷与环境变量：
   - **400** `Pool mode (extensions.poolRef) does not support volumes.`
4. `DELETE /v1/pools/p3-spike` → **204**，预热 Pod 回收。

结论：池 Pod 预创建，无法在分配时挂每会话工作区/状态卷，也无法下发 egress 默认拒绝策略。两项都是本服务的硬约束（C5/数据隔离），因此 **不采用预热池**。降级方案：

- 依赖镜像预拉（kind 已 `kind load`；生产用节点镜像缓存/DaemonSet 预拉）。
- 新增 `cloud_agents_sandbox_create_seconds{mode="create|resume"}` 直方图，持续观测创建/恢复时延，作为是否值得引入其他预热手段的依据。
- 方案文档 §4.3 已回写该偏离。

## 未覆盖风险

- 真实 NFS 上的双卷创建与读写权限（D2）。
- 多副本下 sweeper 只处理本副本持有桥接的通道；跨副本空闲会话由持有桥接的副本处理，无跨副本协调。
- 长 turn（无事件超过空闲阈值）在控制面重启后的极端窗口可能被误判；当前依赖 `turn/started`/`turn/completed` 与持续事件。
- `requestUserInput` 超时策略未实现。
- 审批超时只做了单测，未在 kind 构造真实无人审批场景。

## 复现入口

- 空闲：`POST /api/sessions` → 等待 `IDLE_TIMEOUT_SECONDS + IDLE_SWEEP_INTERVAL_SECONDS` → `GET /api/sessions/<id>`；指标 `/metrics`；审计 `audit_events`。
- 池：`POST /v1/pools` → `POST /v1/sandboxes`（带 `extensions.poolRef`）→ 观察 400；`DELETE /v1/pools/<name>`。
