# 2026-11-18 P1 简化基准（admission / density / resume）

一次性记录。对应实施计划 §7 L6 的简化版：准入、活跃率/资源占用、resume 时延。
结论：**三模式全 PASS**——单活跃准入与拒绝计数对账一致；N=8 并发 306 turn 零失败、
网关 SSE 计数全对账；三种 resume 路径时延 0.04s / 0.23s / 冷恢复 5.3s+0.76s。
开发机数据只作 §2 预算的**参考区间（对话型负载下界）**，预算不据此改数，真值上线后观测。
基准脚本入库可复跑：`bench/load.py`（口径与限制见 `bench/README.md`）；结果 JSON 在 `.local/bench/`（不入库）。

## 环境与版本

- 开发机 Windows，12 核 / 32GB；Docker Desktop VM：NCPU=12、MemTotal≈15.5GiB（`docker info`）。
- OpenSandbox `uvx opensandbox-server` Docker 运行时，execd v1.1.0、egress sidecar v1.1.7（dns+nft）。
- 控制面 `feat/p1-poc`（b3e8dca 后无产品代码改动）；沙箱镜像 `cloud-agents/sandbox:0.1.0`（codex 0.167.0）。
- 模型 DeepSeek `deepseek-flash`（付费公网 Responses API），最小 prompt（"Reply with exactly: …"）。
- 每沙箱硬限 2 vCPU / 2Gi（与产品一致）；egress 默认 deny + 放行网关主机。

## 验证项与证据

### 1. admission：单活跃准入 + churn + 计数对账

| 项 | 结果 |
|---|---|
| 首次创建（冷启动） | 8.4s |
| 第二个创建（同属主） | **429**「同用户已有活跃会话 s-a503…」 |
| 5 路并发 burst 创建 | **5/5 429** |
| 删除后再建 churn ×3 | 全成功，创建时延 5.8 / 5.8 / 5.5s |
| `/metrics` 拒绝计数增量 | **6 = 1+5，与预期一致** |
| 活跃 gauge | 有会话时 1，清空后 0 |

**限制（如实记录）**：P1 API 固定单属主 + 同用户单活跃，全局上限 `max_active_sessions=24`
无法经 API 触达（单测已覆盖该逻辑）；多属主并发准入压测留 P2（OIDC）后。

### 2. density：N=8 并发占空比负载（180s）

构成：1 个 CP 会话（真桥接/WSS 路径，兼网关 token 锚点）+ 7 个 OSB 直建沙箱
（`docker exec -i` 驱动真 codex，L4 已验证路径）。占空比目标 0.3，**实测忙碌占比 0.26**。

| 项 | 结果 |
|---|---|
| 总 turn / 失败 | **306 / 0**（186s 墙钟） |
| turn 时延 | p50 **1.06s**，p95 **3.11s**，max 4.19s |
| 网关 `llm_requests` 增量 | **306 = turn 数**（8 路 SSE 并发经单 worker 网关，零丢失） |
| 每沙箱 CPU（100%=1 核） | 均值 **0.1–0.8%**（≈0.001–0.008 核），峰值 9.6%（≈0.096 核） |
| 每沙箱内存 | exec 驱动 7 个均值 **40–43MiB**；CP 锚点（桥接+codex）**114MiB**，峰值 122MiB |
| 采样 | docker stats 每 5s 触发，25 轮（stats 自身耗时 ~2s，实际间隔 ~7s） |

**硬限超卖实证**：8×2 vCPU=16 > 12 核、8×2Gi=16Gi > 15.5GiB VM 内存——纸面超卖，
对话型负载下无 OOM、无节流失败，印证「cgroup 硬限防单沙箱失控、总量准入防超卖」的分工（§2）。

**与 §2 规划值对照（仅参考，不改预算）**：规划均值 0.3 vCPU / 0.5GB；本次实测
≤0.008 核 / 0.04–0.11GB，低 1–2 个数量级。**原因：负载是最小对话 turn，无工具执行/构建/测试**；
真实 coding 任务（codex 跑命令、装依赖）CPU/内存会显著更高，本数据是**下界**而非代表值。

### 3. resume：三种路径时延（K=10 轮历史）

历史构建：10 轮真实 turn（p50 0.99s），回复 ok-0…ok-9 作回放校验标记。

| 路径 | 时延 | 说明 |
|---|---|---|
| ① 客户端断线重连 + `thread/resume` | **0.04s** | 同沙箱，stdio 不断 |
| ② OSB pause→resume + `thread/resume` | **0.23s** | pause/resume 状态收敛各 ~0.01s |
| ③ 冷恢复：建沙箱 **5.3s** + 全新 codex 磁盘回放 **0.76s** | 合计 ~6s | 10 轮历史校验通过（响应 9284B），续聊 1.1s `resumed-ok` |

对照 L4（1 轮历史）：resume 0.67s / 2645B → 10 轮 0.76s / 9284B，**随历史增长平缓**。
pause 内存语义仍未定论（L10），本条只计时延。

### 4. 清理

三模式均自动清理：`docker ps` 无残留沙箱/sidecar；CP 会话全部 DELETE；服务进程已停。

## 未覆盖风险

- 负载为最小对话 turn：工具执行/构建型负载的资源曲线未测（上线观测或内网复跑时加真实任务）。
- N 路桥接 WS 扇入控制面未覆盖（density 的 7 路走 exec 直驱）；多属主准入竞争未测（P2 前提）。
- 目标并发（24/150）未压：开发机 N=8 为简化版，内网执行机按 `--sessions/--duration` 复跑。
- NFS 卷形态（L5）、长线程（>10 轮）/大状态库 resume 曲线、pause 语义（L10）仍未覆盖。
- 锚点 token 为基准专用手法；恢复沙箱 token 签发属 P3 设计项（L4 清单）。
