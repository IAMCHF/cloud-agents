## 发现并修复的缺陷

| # | 现象 | 根因 | 修复 | 提交 |
|---|---|---|---|---|
| 1 | 模型流式回复报 `UTF8 error: invalid utf-8 sequence` | 网关用 `aiter_raw()` 透传上游 gzip 压缩的 SSE 字节 | 改 `aiter_bytes()`，补 gzip 流回归测试 | `6022389` |
| 2 | 命令执行先报 `bwrap: No permissions to create a new namespace` | 容器内无 user namespace 权限，codex 嵌套沙箱不可用 | 默认 `sandbox_mode=danger-full-access` + `approval_policy=on-request`，可用 `CODEX_SANDBOX_MODE`/`CODEX_APPROVAL_POLICY` 覆盖；隔离边界为容器本身 | `d74bd18` |
| 3 | 浏览器刷新报 `Already initialized` | 真 codex 每进程只允许 initialize 一次 | Relay 缓存首次 initialize 结果，对后续客户端本地应答；补测试 | `d74bd18` |
| 4 | 控制面中断后台账残留 `running` | 单 worker 无通道状态，重启未对账 | 启动时把 `creating/running` 统一标记 `ended`（reason=control_plane_restart） | `d74bd18` |

## 未覆盖项与风险

- 多会话并发、准入限流压测（仅单测覆盖，未做真机并发）。
- 长任务、上下文压缩、断网重连的极端时序。
- 网络出口策略（egress sidecar / 域名白名单）未在真机启用验证。
- Compose 单机部署未实跑；控制面崩溃后会话不可恢复（P1 设计如此，重启只标结束）。
- 前端覆盖率门槛未纳入本地 `check`（本机安全策略拦截覆盖率临时目录批量删除），需跑 `pnpm -C web run test:cov`，CI 必须执行。

## 复现方法

1. 本机起 OpenSandbox + 控制面 + Vite：见 `本地测试指南.md`。
2. 创建会话后执行真模式 E2E：

   ```bash
   cd web
   E2E_REAL_SESSION_URL="http://127.0.0.1:5173/?session=<id>&token=<token>&ws=ws://127.0.0.1:8000" \
     pnpm exec playwright test --config playwright.real.config.ts
   ```

3. 指标与清理：`GET /metrics`；`DELETE /api/sessions/<id>` 后确认无 `sandbox-*` 容器。
