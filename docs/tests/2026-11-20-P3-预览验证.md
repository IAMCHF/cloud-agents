# 2026-11-20 P3 T6 应用预览验证

结论：**PASS**。Web 工作区新增「预览」面板：`POST /api/sessions/{id}/preview` 生成短期签名票据，浏览器经 `<session>--<port>.preview.<base>` 子域访问，控制面按 Host 反代到沙箱 endpoint；HTTP 静态页、Cookie 鉴权的子资源、WebSocket（文本/二进制）均通过。

## 环境

| 项 | 值 |
|---|---|
| 集群 | kind `cloud-agents-dev`，控制面双副本 + Ingress（catch-all） |
| 控制面 | `cloud-agents/control-plane:p3`（T6 工作树构建） |
| 预览域 | `PREVIEW_BASE_DOMAIN=127.0.0.1.nip.io`（nip.io 将 `*--*.preview.127.0.0.1.nip.io` 解析到 127.0.0.1） |
| 票据 | HMAC-SHA256，TTL 3600s；未配置 `PREVIEW_TOKEN_SECRET` 时回落 `P1_AUTH_TOKEN` |
| 测试会话 | `s-dc71976eb4e7479e85d62c6ad9bb99f6`（验证后 DELETE） |

## 1. 沙箱内服务

经终端在沙箱内启动：

```text
python -m http.server 3000 --directory /tmp/preview   # /tmp/preview/index.html = "preview-ok"
python /tmp/ws_echo.py                                 # websockets serve 3001，回显 "echo:<msg>"
```

## 2. 生成预览链接

```http
POST /api/sessions/s-dc71.../preview?token=<session_token>
{"port": 3000}
→ {"url":"http://s-dc71...--3000.preview.127.0.0.1.nip.io/","preview_token":"<signed>","expires_at":...}
```

`port` 限制 1024–65535；会话非 running 返回 409；token 非本会话返回 401。

## 3. 访问结果

```text
GET http://s-dc71...--3000.preview.127.0.0.1.nip.io/?preview_token=<signed>
→ 200 "preview-ok"
→ Set-Cookie: ca_preview=<signed>; Path=/; HttpOnly; SameSite=Lax; Max-Age=3599

GET /index.html   Cookie: ca_preview=<signed>
→ 200 "preview-ok"（子资源不再需要查询参数）

WS ws://s-dc71...--3001.preview.127.0.0.1.nip.io/echo?preview_token=<signed>
→ send "ping"      ← "echo:ping"
→ send b"\x00\x01" ← b"echo:\x00\x01"
```

## 4. 实现要点

- **路由**：根路径 catch-all（HTTP + WebSocket）最后注册，先按 `Host` 解析 `<session>--<port>.preview.<base>`；非预览域返回 404，不遮蔽 `healthz`/`metrics`/既有 API。
- **鉴权**：票据 payload `{s,p,e}` 用 HMAC-SHA256 签名；首次请求放查询参数并落 `ca_preview` HttpOnly Cookie，后续子资源/HMR 自动携带。票据与 Host 的会话、端口必须一致，台账必须 running。
- **反代 HTTP**：目标 `http://<OpenSandbox endpoint>/<path>?<query>`；剥离 `authorization`/`ca_preview`/hop-by-hop 头，`accept-encoding: identity`，`Host` 改为 endpoint 以兼容 Vite 等 dev server 的 host 校验；响应剥离 hop-by-hop、回写 `Location` 到预览域、去掉上游 `Set-Cookie` 的 `Domain`。
- **反代 WebSocket**：与终端共用 `app/api/wsrelay.py` 双向转发；请求头只带改写的 `Origin` 与过滤后的 Cookie；支持 `Sec-WebSocket-Protocol`。
- **前端**：右侧新增「预览」tab，输入端口生成链接，内嵌 iframe + 新窗口打开。

## 5. 缺陷与修复

1. **代理测试读到已消费响应**：`httpx.MockTransport` 的 `content=` 响应在 `stream=True` 下 `aiter_raw` 抛 `StreamConsumed`；测试改用 `AsyncByteStream`，生产路径不受影响。
2. **TestClient Cookie 串请求**：测试客户端按 `testserver` 域保存预览 Cookie，验证“无票据 401”前需清空 jar；真实浏览器按预览子域隔离。
3. **首版反代会转发 `Authorization`**：可能把控制面凭据带入沙箱应用；改为显式剥离。

## 未覆盖风险

- 生产需要通配 DNS（`*.preview.<域>`）与 Ingress/TLS；kind 依赖 nip.io 与 catch-all Ingress，D2 需按真实域名配置。TLS 下 Cookie 才带 `Secure`（按 `PUBLIC_BASE_URL` 判断）。
- 首次请求的 `preview_token` 在 URL 中，会进入 Ingress/控制面访问日志；TTL 3600s，生产可改短期票据 + Referer 策略。
- 反代不改写 HTML/JS 内的绝对地址：若 dev server 以 `Host` 生成绝对 URL，仍可能指向沙箱 IP；已回写 302 `Location`，其余需应用使用相对路径。
- 未限流、未限制请求体大小；预览与终端同属会话 token 权限范围，任何持有者均可生成票据。
- 部分应用返回 `X-Frame-Options`/CSP 时 iframe 为空，需用「新窗口打开」。
- 预览服务随会话休眠/结束立即不可用（台账校验），无独立保活。
