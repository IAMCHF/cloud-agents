## 缺陷与观察

1. **Ingress 下的 WS 握手重试**：控制面滚动更新后，旧 Pod 仍可能在 Service endpoints 中短暂存在；客户端若命中无桥接副本/正在终止的 Pod，会收到连接被重置（websockets 报 `InvalidMessage`），而不是稳定的 HTTP 403。Ingress 的 `proxy-next-upstream` 对升级连接的重置不总是重试。本次开发机验证客户端已加入 1s 退避重试；Web 端自动重试列入 P3 T7。
2. **DELETE 后立即 GET**：可能短暂返回 `sandbox_state=Stopping`；Pod 随后回收，属预期。
3. **双卷**：每会话现在创建 `ws-` 与 `state-` 两个 PVC；开发机 local-path 权限正常（`/home/agent/.codex` 可写）。真实 NFS 上非 root 写权限需 `fsGroup`/目录权限策略，留 D2（P3 T3 一并复核）。
4. **旧 token**：休眠后旧 token 在台账中仍可定位但状态为 `idle`，WS/网关活跃校验拒绝；恢复时轮换 token，旧 token 查不到。已由单测覆盖（`test_sleep_and_cold_resume_keep_volumes_and_rotate_token`）。

## 未覆盖风险

- 真实 NFS/跨主机 SQLite 状态盘；真实内网模型与 OIDC 本轮未复跑（P2 已验 OIDC）。
- 空闲自动销毁（sweeper）尚未接入；本轮用显式 `POST /sleep` 验证冷恢复链路。P3 T2 实现。
- 旧 PVC（P2 遗留 `ws-s-2fcfb...`）与本次测试 PVC 未清理；P3 T3 归档/保留任务统一处理。
- 预览/终端/文件树依赖的 execd/Ingress 能力未在本轮验证。
